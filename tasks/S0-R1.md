# S0 第一轮任务单

状态：待实施。当前只做启动准备，不生成业务代码、不安装项目依赖、不启动应用。

## 本轮目标

交付一个最小技术支持工作台，让用户看到一句需求如何经过实现、PR、独立审查和运行验收成为可用产品。S0 允许 Agent 全程推进，用户可以旁观或体验。

第一条业务流程：输入问题 → 保存工单 → 列表查看 → 打开详情 → 重启后记录仍在。

- 根仓库：[AutsKlam/studyprojects](https://github.com/AutsKlam/studyprojects)，保存规划与学习证据。
- 阶段项目的计划位置：`projects/s0-support/`，本轮准备期间不创建。实施时初始化独立 Git 仓库；不把业务源码提交到根仓库。
- 阶段远端：尚未确定，不复用根仓库存储业务代码。拟用独立 S0 仓库，建立前确定具体地址与可见性。
- 代码基线：尚不存在。实施时记录首个基线 commit，再通过功能分支和 PR 推进本轮。

## 最小范围

1. 工单：录入标题和问题描述，查看列表与详情。
2. 资料：手动录入标题和正文，查看资料列表与详情，为后续资料问答提供输入。
3. 数据：使用本地 SQLite 持久化，提供少量可重复导入的演示数据。
4. 运行：前后端独立进程，提供 Windows PowerShell 启动、停止脚本及首次安装说明；显示访问地址和可排查的错误。
5. 交付：README、必要验证、PR、独立审查记录和简短交付卡。

范围外：模型调用、RAG、文件解析、账户系统、复杂权限、云部署、业务多智能体。后续需求进入相应阶段。

## 技术选择

- 前端：React、TypeScript、Vite，使用本机 Node 与 npm。
- 后端：Python 3.12、FastAPI；数据库使用 SQLite。使用 uv 管理后端环境并保存依赖锁定文件。
- 启动脚本优先适配当前 Windows 环境，不要求 Docker 或 pnpm。
- 实施时选择相容依赖版本并锁定；当前没有安装或运行项目依赖，不能将环境检查视作应用已验证。

已核对的官方入口：[Vite 入门与环境要求](https://vite.dev/guide/)、[FastAPI 文档](https://fastapi.tiangolo.com/)。具体版本如果需要调整，记录在任务与 plan 中，不改固定大纲。

## 验收条件

| 编号 | 要验证的行为 | 证据 |
| --- | --- | --- |
| A1 | 按 README 安装后，通过启动入口运行前后端并打开页面 | 命令、环境与浏览器操作记录 |
| A2 | 提交非空问题后，列表与详情显示同一条工单；空输入有明确提示 | 浏览器端到端操作与相应接口验证 |
| A3 | 停止并重启应用后，已创建的工单与资料仍存在 | 同一记录重启前后的验证 |
| A4 | 可以录入并查看一条资料；演示数据重复导入不会反复增加同一批记录 | 操作记录或有意义的集成检查 |
| A5 | 启动失败可定位原因；停止脚本只停止本项目进程 | 对脚本的检查和实际运行验证 |
| A6 | 功能通过真实 PR 提交，Reviewer 检查实现与运行结果 | 阶段仓库 PR、审查版本及验收结果 |

尚无阶段远端时允许准备本地改动与审查，但 A6 保持未完成。没有模型密钥不会阻塞 S0。
